# 1.3.0 — Consistency and reproducibility plan

Design document produced during a brainstorming pass on the repository. It records
what was agreed, why, and what is deliberately out of scope, so the next release
can be reviewed against it.

## 1. Understanding summary

- **What:** a quality pass on the extension, released as **1.3.0**. No new
  user-facing features.
- **Why:** the repository contradicts itself in several places (documentation
  claims one behaviour while the code does another), and every guarantee verified
  during development was lost because the test harnesses lived outside the repo.
- **Who:** one user and one maintainer, on their own machine, installing the VSIX
  from a GitHub release.
- **Constraints:** the panel must work fully offline; the monolithic webview is not
  being split up; verification is one reproducible script; no Marketplace
  publication.
- **Non-goals:** Marketplace content policy and metadata, splitting
  `src/webview.html` into CSS/JS modules, eslint/prettier, a broad CI test matrix,
  internationalisation, new features, and changing the UI language (Vietnamese UI,
  English documentation stays as-is).

## 2. Assumptions

1. **Performance is irrelevant.** A sync writes at most three files under 80 KB;
   nothing is optimised.
2. **Reliability is best-effort.** Locked, read-only or cloud-synced files surface
   the existing error path (`showErrorMessage`); no retries are added.
3. **The `.lunabak` sidecar is sufficient** protection against data loss; no
   multi-version history is kept.
4. **`preview: true`** in `package.json` is now meaningless without a Marketplace
   listing, but it is left untouched.

## 5. Design

### WS-A — Truly offline panel

Remove the Google Fonts `<link>` and the two font hosts from the CSP. Map
`--font-ui` and `--font-mono` onto the editor's own font variables
(`--vscode-font-family`, `--vscode-editor-font-family`) with a monospace
fallback, so the panel inherits the user's theme instead of a fixed web font.
Result: `default-src 'none'`, no external host in the policy, no request when the
panel renders.

### WS-B — One line-ending convention

Add `.gitattributes` with `* text=auto eol=lf` plus explicit binary markers for
`*.png` and `*.vsix`. LF matches `.editorconfig`, which is the file contributors
actually read. Normalising the working tree proved fully content-neutral for git —
the files whose line endings changed produce no diff at all — so it needs no
commit of its own and only `.gitattributes` is new.

### WS-C — Debug configuration that matches the docs

Add `.vscode/launch.json` (Extension Development Host) and `.vscode/tasks.json`
(`npm: watch`) so the documented F5 flow works. `.vscode/**` is already excluded
from the package.

### WS-D — Remove dead loader fallbacks

Reduce each profile's candidate filename list to the single real name
(`bypass_v1.md`, `bypass_v2.md`, `bypass_v3.md`). The other six names do not exist
on disk and only obscure the loader.

### WS-E — Version and changelog discipline

Fix the repository URLs to `hieuday88/agent-safety-jailbreak-lab` and merge the
1.2.2 changelog section into 1.3.0, stating explicitly that 1.2.1 and 1.2.2 were
never published. Rewrite the section so it reads as a list of what changed in the
product; the brand rename is one entry, not the headline.

### WS-F — Reproducible verification

Commit the three verification suites under `test/` and expose them as
`npm test`:

| Suite | What it proves |
|---|---|
| `test/behaviour.js` | Target scoping, `.lunabak` backup and restore, upgrade migration, shared notice wording, non-destructive deactivation |
| `test/consistency.js` | Cross-file audit: versions, brand versus repository location, profile count, the no-network claim **including the panel's own network surface**, documented paths, packaging, artifact naming, build scripts |
| `test/ui.js` | Drives the real webview script in a DOM shim: toggles drive the payload, the banner shows the host wording, CSP and markup stay truthful |

`test/**` is excluded from the package.

### WS-G — Say when the profile takes effect

State the new-session requirement in the sync and removal notices for every
environment, and in the README, because an assistant composes the profile into its
instructions when a session starts and an open session keeps the one it began
with. The behaviour suite asserts that a Gemini-only sync still asks for a new
session; the audit asserts the Claude-only wording is gone.

### WS-H — Release

1. `git checkout main && git merge --ff-only fork`
2. `npm ci && npm run check && npm test`
3. `npm run package:release`
4. `git tag -a v1.3.0 -m "Luna rebrand, environment scoping, backup sidecars"`
5. `git push origin main && git push origin v1.3.0`
6. Create the GitHub release and attach
   `agent-safety-jailbreak-lab-1.3.0.vsix` (it is gitignored, so it can only travel
   as a release asset)

## 6. Verification strategy

- `npm run check` — TypeScript with `strict`.
- `npm test` — the three suites above, all must pass.
- Inspect the packaged VSIX: manifest version and publisher, no pre-rename brand
  token outside the legacy migration constants, no network hosts, and `test/`,
  `docs/` and `scripts/` absent.

## 7. Risks

- **The push is not easily reversible.** The release is public.
- **The publisher changed**, so an existing installation is not upgraded in place;
  the previous package must be uninstalled first. The extension cleans up the
  output style left by the pre-rename release on the next sync.
- **EOL normalisation touched every tracked file** while git recorded no content
  change at all, so it produced no churn and needed no commit of its own.
